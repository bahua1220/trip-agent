# GitHub 发布检查清单

本次工具只准备本地候选目录，不登录 GitHub、不创建远端、不推送、不发布小程序、不部署后端。

## 已识别的原仓库问题

- 活跃 Git 根目录位于项目父级，包含无关项目，不能直接整库上传。
- `frontend/.env` 已进入可达 Git 历史，并含非占位配置值；运行配置不能连同旧历史发布。
- 本地有 `.env`、部署副本/压缩包、日志、用户行程与评测产物，应全部隔离。
- 旧 README 对框架与流程的描述过时；本次按现有实现更新。
- 项目级授权尚未核清：原 README 声明 CC BY-NC-SA 4.0，缺少 LICENSE，模板中另有许可字段，不能据此擅自把全部代码改为 MIT。

这些是本地发现，不证明旧仓库曾经公开，也不等于已经完成密钥轮换。

## 候选目录

`scripts/prepare_github_snapshot.py` 只复制白名单代码、测试、示例配置与文档；不复制 `.git` 和其他项目。可额外带入实际小程序正在使用的页面与入口。导出时替换生产 API 地址、清除 AppID、去除已知回归样本的真实任务编号。

每次导出使用新的空目录，不覆盖旧快照；输出清单列出文件及 SHA-256。候选目录通过后仍仅是“可审查副本”，不是已确认授权的公开发行版。

## 公开前仍需确认

- [ ] 核查历史运行配置中的地图凭证与限制；若存在暴露可能，按供应商流程轮换并验证运行环境。
- [ ] 核对代码、模板及资源来源，确定允许分发的范围并补齐 LICENSE / NOTICE；不伪造作者署名。
- [ ] 如要公开截图/录屏，去掉用户身份、真实行程、内部域名及敏感信息，确认有权展示。
- [ ] 从候选目录重跑后端、前端逻辑及 Web 构建；单独做小程序编译/真机验收。
- [ ] 在 GitHub 创建独立仓库，先使用私有可见性；核对所有待上传文件再推送。
- [ ] 由项目所有者确认仓库名称、账号与最终公开范围。

此次不添加虚构用户量、成功率或“全平台完全验证”的徽章。缺少公开截图/演示材料时如实保留空缺，不伪造效果。

## 推送边界

不要在原父级仓库执行 `git add .`、直接添加远端或改写历史。后续如要推送，应在已审查的独立候选目录建立新仓库，保留来源说明，不把有风险的旧历史搬过去。创建远端、上传代码和从私有转公开需另行确认。
