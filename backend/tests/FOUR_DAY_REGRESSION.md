# 南京四天失败回归（2026-10-29）

来源：任务 `22f5f089-978f-4d40-99e1-79e5a53f76b0` 的服务器日志。
原条件：南京四天、适中节奏、无兴趣、10:00高铁抵达、末日07:01高铁离开。
原结果：62条POI粗筛20条后归并成5组；一组混杂了老门东、夫子庙及普通商家，
整组被隐藏。模型只给第三天排了古鸡鸣寺，换日后中间两天形成3/1分布，最后
质量检查因完整日只游览90分钟而拒绝返回。

## 本轮修改

- 景点入口拒绝明确的普通餐饮/零售POI，保留文化书店和实际美食街等例外。
- 子景区继承总景区的代表性后，只隐藏总景区POI，不再删除整组。
- 独立子景区集合参与归并，防止别名传递把两个独立子景区连在一起。
- 不再凭任意相同的三个字归并不同地点。
- 使用已有搜索结果先打分、归并，再按独立实体预算截断，不增加模型或地图请求。
- 单城市最终补位前尝试3/1→2/2的均衡；不移动用户锁定项，不动抵离短日，
  试算两天真实路线、饭点、开放时间，不删除原景点。多城市不进入此均衡规则。
- 雨雪天补位时优先可行的明确室内候选，无法找到可行候选时仍保留质量门禁。
- 景点补排失败不再默认要求用户修改旅行天数。
- 小程序失败态不显示100%，不承诺自动继续，失败步骤显示“未通过”，后续步骤
  显示“未执行”。正常断线恢复和成功查看行程不变。

## 验证

在项目根目录运行：

```powershell
python backend/scripts/run_offline_tests.py
node --test frontend_miniapp_patch/tests/*.test.cjs
```

`test_four_day_candidate_repair.py` 的检查覆盖上述结构，包括最终完整排程，
源数据位于 `fixtures/nanjing_four_day_failure.json`。它是从日志缩减的结构性样本，
不是完整高德原始响应；坐标/路线为固定适配器，日期移到未来以免受测试时钟影响。
前端测试会执行实际页面状态函数，桌面环境中还会验证HBuilder项目对应源码。

这轮未调用真实付费接口，未重编译发布小程序、未部署服务器；离线通过不能替代
更新后对同样四天抵离条件的真实生成和手机体验版验收。

后续真实四天复测完成了主流程，发现07:01早离日无餐饮/景点时漏算退房。
已补20分钟退房/整理行李，并加入独立审计检查；有早餐的离开日不重复加时。
清晨/深夜公共交通另给出首末班未核验的警告，不把参考耗时当成运营证明。
这处小修用本次真实返回的45分钟接驳做离线复算，未反复调用付费生成。

真实测试入口已增加显式选择的 `--case single-four-day`；默认三条批量不变。
该用例把两端站点固定为南京南站，只复测关键结构，不宣称精确还原日志未记录的站点选择。
