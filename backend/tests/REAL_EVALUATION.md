# 真实接口小批量评测

先离线验证排程和隔离，再用少量真实请求检查模型与外部数据质量。
本工具不修改业务排程规则，不启动服务器，也不写入用户历史或任务数据库。
它调用生产规划器 `plan_trip`，使用本地配置的真实模型、高德、天气和搜索服务。
HTTP/后台任务的离线集成测试仍由原来的 `run_acceptance.py --suite all` 负责。

## 三个场景

| ID | 条件 | 重点 |
|---|---|---|
| single-default | 南京3天，公共交通，不填抵离和兴趣，适中节奏 | 景点是否充足，三餐是否顺路，下午是否空白 |
| single-timed | 西安3天，12:00西安北站抵达、17:00该站离开，轻松节奏、历史文化和当地美食 | 抵离接驳与候车缓冲，节奏与偏好是否生效 |
| multi-rail | 江西5天，南昌→景德镇，高铁跨城；首日12:00南昌西站到、末日18:00景德镇北站走 | 换城窗口与分段交通、城市归属、两端枢纽 |

定义在 `fixtures/real_trip_cases.json`。日期由命令统一注入，默认上海时区今天起7天后。

另有默认不运行的 `single-four-day`：南京四天、适中、无兴趣，10:00高铁抵达、
末日07:01高铁离开，两端固定南京南站。它对应10月29日失败案例的关键结构，
并非完整原始请求重放；不会增加默认三条的付费批量。需要真实复测时显式执行：

```powershell
python backend/scripts/run_real_evaluation.py --case single-four-day --execute --confirm-paid
```

不强求某份唯一行程，也不把某个经典景点指定为必选。当前不是完整测试矩阵，
还没有覆盖亲子、所有游玩节奏、所有交通模式、节假日等组合。

## 默认预览，不产生接口用量

在项目根目录的PowerShell执行：

```powershell
python backend/scripts/run_real_evaluation.py
```

只生成三份合法请求和HTML预览，状态为“未调用真实接口”，**不算测试通过**。
不会创建模型客户端或调用地图。每轮生成独立时间戳目录，不覆盖旧报告。

## 真实运行（会消耗额度）

使用 `backend/.env` 或已有环境变量中的密钥，不要把密钥贴到命令行或聊天里。
最低需要 `LLM_API_KEY`/`OPENAI_API_KEY` 和 `AMAP_API_KEY`；Tavily为可选配置。
与应用一致，可通过 `LLM_BASE_URL`、`LLM_MODEL_ID` 等选择供应商。

建议先只跑南京一条：

```powershell
python backend/scripts/run_real_evaluation.py --case single-default --execute --confirm-paid
```

确认后跑全部三条：

```powershell
python backend/scripts/run_real_evaluation.py --execute --confirm-paid
```

可加 `--start-date 2026-11-04` 指定未来的日期，或用 `--case` 选择用例（可重复）。
`--output-dir` 指定产物根目录；`--timeout-seconds` 指定单条时限，默认900秒。
串行运行，最多三条，不做测试脚本级自动重试；生产SDK/规划器内部重试保持原样。
遇到执行异常或超时即停止后续请求；确定性的质量检查失败/降级则保留结果并继续。
超时或Ctrl+C会终止该条进程，已发出的远程调用仍可能计费。
**一条旅行请求会产生多次服务调用，不保证固定费用或费用硬上限。**

## 报告与审阅

控制台打印本轮 `report.html` 的完整路径，默认在：

```text
backend/test-results/real-evaluation/<时间戳-随机后缀>/
  report.html                 汇总、人工审阅问题及逐日时间轴
  report.json                 机器可读汇总
  <用例ID>/
    request.json              本轮实际请求（包含日期和默认值）
    run.log                   生成过程及异常堆栈，尽力脱敏
    progress.jsonl            带时间的阶段进度
    tripPlan.json             有返回结果时保存，包括降级结果
    checks.json               自动检查，有行程结果时生成
    result.json               最终状态、耗时及错误
```

独立检查包括：日期和请求一致、时间重叠/溢出、饭点、可解析的数值营业时间、
景点重复、地点与时间轴引用同步、缺餐、完整日下午空白、景点数量偏少、
交通起终点、长市内通勤、跨城铁路两端车站与接驳、抵离所选枢纽、候车缓冲、
预算加总。另合并并标注生产校验器的问题，不把它当成独立检查的替代品。

复杂的星期/季节营业规则、缺失信息、现场用餐建议、稀疏日程等单独警告，
不凭猜测判断“已验证”。自动检查使用供应商返回的文本，并未另查官网或12306。
铁路参考时间也不会自动证明真实班次存在。

自动通过仍标明“待人工审阅”。你重点看：景点代表性、是否值得安排、餐厅是否
有地方特色且适合堂食、酒店选址及全程体验。不能仅凭POI存在或评分断言推荐靠谱。
**只有人工审阅后，才能给出整份行程是否合格的结论。**
真实执行仅在全部选中用例自动通过时退出0；失败、降级、异常、超时或剩余未运行则退出1。
预览成功退出0仅表示准备成功。已保存产物仍建议分享前检查隐私和密钥。

发现问题后保留本轮目录、指出日期/地点/不合理原因，再把数据缩减成离线回归场景，
修复后先跑离线测试、再重跑对应的一条真实场景；不自动循环付费重试。

## 测试工具自身的离线验证

```powershell
Set-Location backend
$env:PYTHONPATH='.'
python -m unittest discover -s tests -p test_real_evaluation.py -v
```

测试覆盖默认不联网、双开关保护、密钥缺失、异常止损、进程超时、日志脱敏、
独立规则、HTML转义、生成成功/降级/失败的产物；这些工具测试不消耗接口额度。

全量离线回归建议从项目根目录用带外网拦截的入口，不要直接跑未加保护的全量discover：

```powershell
python backend/scripts/run_offline_tests.py
```

拦截非回环地址的DNS和连接；即使业务代码吞掉异常并返回兜底，仍会因为有外网尝试
而使回归失败。HTTP集成测试需要的本机回环连接继续允许。
