# 旅行规划八条离线验收

真实模型/地图的小批量测试见 [REAL_EVALUATION.md](REAL_EVALUATION.md)。
它默认只准备三类请求和预览报告，必须显式开启才消耗接口额度；不能用离线结果代替真实质量评测。

本套件来自用户确认的八条行为要求。它使用固定日期、景点、餐厅、营业时间、
逐段交通和模型候选编号结果，不调用真实模型、高德或 Tavily。
套件会禁止套接字连接，避免因代码兜底吞掉网络错误而误报“离线通过”。

## 运行

在项目根目录的 PowerShell 执行：

```powershell
python backend/scripts/run_acceptance.py
node --test frontend_miniapp_patch/tests/transport_choices.test.cjs
```

完整运行这八条、任务隔离和HTTP全流程测试：

```powershell
python backend/scripts/run_acceptance.py --suite all --output-dir backend/test-results/system-offline
```

也可用 `--suite isolation` 或 `--suite pipeline` 单独运行。

全量后端离线回归用 `python backend/scripts/run_offline_tests.py`。
此入口及上面的验收入口都会拦截外网DNS/连接；即使业务捕获异常，外网尝试也会让回归失败。

## 会话隔离与完整流程

- 规划器现在每次任务/编辑创建独立实例，候选、餐饮缓存、拒绝列表、酒店地域、
  动态城市坐标均独立；模型客户端及无检查点的Agent图复用。
- 7条隔离检查涵盖：并发交错、客户端复用、失败后工作线程复用、城市缓存不污染
  类级默认值、同时首次初始化，以及客户端初始化失败后重试。
- 5条全流程检查涵盖：南京单城市、江西多城市、两个用户不同日期与偏好并发、
  编辑会话隔离，以及搜索失败后新任务恢复。
- 全流程真实经过HTTP入口、权限依赖后的用户隔离、后台任务、候选筛选/解析、
  酒店选择、餐饮选择、时间轴、质量报告、预算及历史保存调用。
- 登录身份和内容检测在测试中替代；任务数据库使用MemoryTripTaskStore，
  历史保存用记录器替代MySQL，外部服务使用 `fixtures/pipeline_cities.json`
  和 `pipeline_fixture.py`。这不是线上服务、微信真机或MySQL集成测试。
- 并发测试用屏障保证两个任务在餐饮阶段交错，不依赖“碰巧同时执行”。
- 新流程测试发现并覆盖了一个旧规则矛盾：短途跨城日两个景点已经满足时间约束，
  最终强度裁剪仍硬删成一个。现在仅在跨城不足4小时、并非赶路日、实际时段无
  硬冲突且日程跨度合格时允许保留两个；长途/赶路日仍限制一个。

第一条生成 `backend/test-results/acceptance/report.html` 和 `report.json`，
以及逐条用例的完整行程 JSON。任何失败、执行异常或跳过都会使命令退出码非零。
也可以用 `--output-dir backend/test-results/my-run` 指定独立报告目录。

## 验收标准

| 编号 | 场景 | 核心检查 |
|---|---|---|
| 01 | 南京四天，无抵离与兴趣 | 固定经典候选未因餐饮丢失、每天三餐、至少两个可行景点、不重复 |
| 02 | 已选南京站/南京南站，时刻留空 | 两端枢纽保留且时刻为空；其余时间轴与未选枢纽时完全一致 |
| 03 | 12:00高铁抵达 | 出站20+接驳30+入住20，13:10整理完成；先午餐再游览；午餐不晚于14:00 |
| 04 | 10:00高铁离开 | 早餐45、退房20、接驳35；不早于07:00吃早餐，最迟09:00到站；无多余景点与午晚餐 |
| 05 | 15:30开始、博物馆17:00闭馆、需120分钟 | 博物馆换日或备选，不压缩游览；晚间可行街区保留 |
| 06 | 午餐A绕行，沿线有营业门店B | 换为真实B且坐标正确；两个可行景点保留；午晚餐时段及营业约束均满足 |
| 07 | 南昌上午游览，午后去景德镇 | 上午活动先完成；真实窗口选择；酒店到站、铁路、到站后酒店接驳可辨；铁路标明参考 |
| 08 | 用户改步行后添加景点并重排 | 同起终点保留步行；清空时间轴及JSON往返不丢选择；引入闭馆冲突后明确报错且不删用户景点 |

01–06、08的正常结果额外独立检查：事件无重叠、时长与起止时间一致、
午晚餐不超时、营业时间覆盖活动、景点不重复，并执行现有后端质量校验。
07专门检查跨城窗口与分段时间轴；它不作为整个多城生成流程或景点选取的质量结论。

## 边界

- 01固定候选与模型编号结果，仅证明解析和后续排程不会破坏这些候选，不能证明真实模型一定选得好。
- “经典景点是否充分”“真实搜索质量”“真实营业时间是否准确”仍需独立的在线评测与人工抽查。
- 8条用例不是对任意输入的正确性证明；发现新问题应保存数据并增加回归场景。
- 不固定整份行程为唯一答案，优先检查约束和内容保留；固定耗时的算术关系可以精确断言。

首次修复前的报告在 `backend/test-results/acceptance-before/report.html`，
修复后报告在 `backend/test-results/acceptance-after/report.html`。
